# Contributing to DomasPad

Thank you for your interest in contributing!

## Getting Started

### Prerequisites

- Node.js 18+
- npm
- macOS (the app is macOS-only)

### Local Setup

```bash
git clone https://github.com/<your-fork>/domaspad.git
cd domaspad
npm install
npm start
```

`npm start` bundles the renderer and launches the app in development mode. DevTools are available via **View → Toggle Developer Tools** in dev builds only.

### Project Structure

```
domaspad/
  main.js           Electron main process — window, menus, file I/O, session
  preload.js        IPC bridge between main and renderer (contextBridge)
  renderer/
    index.html      App shell (DOM structure)
    app.js          Application logic — tabs, editor, themes, session (source)
    bundle.js       Generated by esbuild — do not edit, not committed to git
    styles.css      All styling — dark and light themes
  ARCHITECTURE.md   Complete technical specification
  CHANGELOG.md      Version history
```

## Making Changes

### Renderer changes (`renderer/app.js`)

The renderer uses ES module imports that are bundled by esbuild into `renderer/bundle.js`. After editing `app.js`, the bundle is rebuilt automatically by `npm start`. To rebuild without launching:

```bash
npm run bundle
```

### Main process changes (`main.js`, `preload.js`)

Restart the app after editing. No bundling needed.

### Styling (`renderer/styles.css`)

No build step — the CSS is loaded directly. Restart or reload the window to see changes.

## Code Style

- Plain JavaScript (ES2020+), no TypeScript, no frameworks in the renderer
- Follow existing patterns — single CodeMirror instance, IPC for all file I/O
- All file access must go through the `allowedFilePaths` allowlist in `main.js`
- Do not re-introduce `innerHTML` for user-controlled content — use DOM APIs

## Submitting a Pull Request

1. Fork the repository and create a feature branch
2. Make your changes with a focused scope — one fix or feature per PR
3. Test by running `npm start` and exercising the affected functionality
4. Open a PR with a clear description of the change and why it's needed

## Reporting Issues

Please open a GitHub issue with:
- macOS version
- DomasPad version
- Steps to reproduce
- What you expected vs. what happened
